## 2. 这一阶段怎样算完成

先取得一轮可核对的 v0.12.0 板端结果，并修复这轮暴露的实际问题；时间系统的核心方向已由用户确认，当前完成该增量的需求、设计和用例登记；其他候选仍待后续选择。

验收目标是玩家能够走完校园生活、体验短游戏和声音、保存后继续手账。下一组功能应能回答三个问题：玩家多了一件什么可做的事、小猫怎样回应、完成后留下什么可见变化。

| 顺序 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| A | 最新固件实机验收 | 有声视频、启动及保存/复位日志；按用例区分通过、失败与未覆盖 |
| B | 根据证据调优 | 每个问题有触发步骤、修复、重测；关键路线与存档回归 |
| C | 确定下一组养成内容 | 用户确认范围、交互和成功标准；补齐正式需求/设计/用例 |
| D | 制作与实现 | 复用画风和导航，小步实现；主机、界面及目标构建验证 |
| E | 新增量实机与交付 | 新版本实测、固件、容量记录、操作说明与真实测试结果齐全 |

工程验证继续按 A、B 安排；用户确认的时间系统先进入 C 的文档设计，保存布局在编码前评审。等待实机反馈期间，可以继续审阅方案、整理文档和素材预算。

## 3. A：用一次生活路线集中验收

使用[声音版固件及听音说明](C:/Users/30831/Desktop/大三上/周六软件产品综合开发/outputs/pet-shahe-audio-v012-20261107/v0.12.0-烧录与听音验证.md)。保留原存档；根据当前手账页选择能覆盖的操作，不要求清档，也不要求重做 T0/T1。

建议按以下路线拍摄，时间由实际游玩决定：

1. 在宿舍打开状态页，核对 v0.12.0、饱食/心情和声音模式。连续听至少两轮音乐，约32秒，观察接缝和触摸响应。
2. 点门出宿舍，沿路进教室上课。进入记忆题，分别试展示期误点、答错、退出和正常完成；检查四种图案与提示音的对应、背景是否压低。
3. 去食堂吃饭，再去健身房锻炼。观察家具绕行、动作反馈、实际数值和原门返回。
4. 回宿舍下外卖，配送期间可以正常走动或进行其他活动。送达后点纸袋领取，确认袋和房门互不误触。
5. 上床休息并醒来，查看手账。若本页三项已完成，领取贴纸，检查只领一次并翻页；未完成则保留该页，不预判通过。
6. 切换“仅音效”和“静音”，观察音乐、短音和原玩法。选静音、等待“已保存，重启可恢复”后复位，核对声音模式及手账/数值/订单；另一次验证音乐模式保存恢复。

| 证据 | 应能核对什么 |
| --- | --- |
| 实际启动串口 | 版本、WORLD、SAVE-TEST、AUDIO-TEST 各项结果，声音工作线程与存档加载状态 |
| 有声操作视频 | 当前版本、主要路线、记忆题提示、模式切换、连续音乐和实际触摸表现 |
| 保存与复位串口，配合画面 | 确认成功保存后，恢复的模式、手账、订单和数值一致 |
| 问题复现记录 | 操作地点、点击顺序、当时状态、实际现象；出现频率按实际记录 |

本路线可以同时采集 TC-190、TC-196、TC-202 的相关证据，判定仍逐项对照[测试计划](D:/project/sifli/course_starter/docs/03-测试计划.md)。一次视频没有覆盖到的判据继续留空；主机日志与 WAV 试听不替代板端。

## 4. B：先改哪些问题

收到证据后，按影响排序处理，复现后再确定原因。

| 优先级 | 处理对象 | 回归重点 |
| --- | --- | --- |
| 最高 | 崩溃、卡死、触摸无法继续、存档丢失或奖励重复 | 原始失败与修复后证据分开保存；确认数据与核心路线 |
| 高 | 声音明显断续、音量不合适、四音难区分、声画错位，或门/家具容易误点 | 修改前后使用相同操作对照；检查静音、切场景与游戏 |
| 后续 | 提示难懂、活动节奏单调、摆设或动画反馈不足 | 先明确玩家的问题，再决定文字、数值或素材调整 |

如果只是现有功能修正，可按修复版本交付，版本号在实际变更时确定。音频异常不改写为游戏成功或失败；数据恢复问题优先于增加内容。SDK 原文件的告警与应用缺陷分别记录。

## 5. C：时间系统与后续养成候选

时间系统的流速、暂停与活动限制已由用户确认，详见独立方案和REQ-191、REQ-192、REQ-193、REQ-194、REQ-195。下表A/B/C仍为AI候选，D已完成方向确认和文档登记，尚未实现。

| 候选 | 玩家可以做什么 | 与现有内容的关系 | 新增成本与验收方向 |
| --- | --- | --- | --- |
| A：贴纸收藏与小猫需求提示 | 回看已获得的三组贴纸；看懂小猫当前更适合吃饭、休息或活动 | 延续手账和双数值，让照料与收集更容易被看见 | 优先复用现有贴纸收集位和数值；检查未解锁/已解锁、提示与实际可操作状态一致 |
| B：室内生活小互动 | 例如照料宿舍盆栽、整理书桌、在窗边停留看风景；首批从中选少量互动 | 回应“室内内容更丰富”，让已完成的房间布置参与玩法 | 逐项标注触摸区、落脚点、绕障和反馈；不把每件摆设都直接加按钮 |
| C：第二个短小游戏 | 例如食堂配餐，用少量点选组成一次短挑战 | 为养成穿插另一种变化，完成后回到校园生活 | 先确认规则与奖励，再估算素材和存档；失败惩罚不默认加入 |
| D：24小时校园日程（方向已确认） | 一天内体验早晨、上课、三餐、晚间与休息；非上课时自习、非饭点简餐 | 为现有校园生活组织节奏，现实30分钟一日、关机暂停 | 已登记需求/设计/用例；保存布局需评审，源代码尚未实现 |

**当前优先完善 D 的设计。** A仍建议作为此后养成扩展，让已获得的贴纸可回看，并让小猫需求更易理解；B和第二个小游戏继续保留。

选择 A 时的建议边界：

- 收藏页先展示现有三组贴纸、解锁状态和当前页/数量。现存档没有每次获得的时间、地点与历史流水，不直接展示这类未记录信息。
- 需求提示由现有饱食、心情、睡眠、忙碌及冷却状态推导。提示应与当时能做的事一致，不新增第三项数值。
- 满值时解释当前状态，避免提示玩家去做随后必然被拒绝的动作；具体提示优先级在需求登记时确认。
- 现有“点路走、点门进出”、固定室内镜头、左上位置提示和清爽绘本风继续沿用。

称号、装扮、商店、货币、签到、更多房间等可以进入后续讨论，本批只在选定候选后列清必做范围。本文不替用户确定这些扩展，也不将暂缓内容记为删除。

## 7. 资源和交付约束

当前剩余程序区约1.07 MiB，后续优先复用已有房间、图标、字体和声音。每增加一份整图或音轨都先估算，实际构建仍以 **ROM < 8,388,608 字节** 为硬性条件；ZIP 大小、main.bin 大小与链接程序区占用分别记录。

运行时内存、音频持续播放、音乐与触摸并行需要板端结果。保持纯 C 规则与 LVGL 展示边界、独立送音和原双区存档；出现需要改动这些边界的新功能，先提出取舍，不在实现中顺带替换。

每批交付应包括固件及下载文件、操作说明、构建元数据、主机验证和实际实机结果。尚未取得的证据明确待补，不能由包校验或主机截图补成通过。
