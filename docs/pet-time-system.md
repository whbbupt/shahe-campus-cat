# 沙河校园小猫：24 小时时间系统方案

2026-11-07 · v0.12.0 之后的计划增量 · 文档设计，尚未实现

## 1. 已确认的方向

用户已明确选择：

- **现实30分钟＝游戏24小时**，流速48倍。
- **关机暂停，开机继续**，不补算关机期间过去了多久。
- **活动按时段区分，并保留替代活动**。白天上课、晚上自习，饭点吃正餐，其他时间仍能照料和游玩。

这是一只小猫自己的24小时校园日程，显示“第几天、几点几分”。用户说的现实作息用于组织生活节律，不要求游戏钟与电脑或手表现实钟保持同一时刻。具体时间窗、初始时刻和数值是下面的AI初版参数；已有方向与这些参数的来源分别记录。

| 现实经过 | 游戏经过 |
| --- | --- |
| 1秒 | 48秒 |
| 1.25秒 | 1分钟 |
| 75秒 | 1小时 |
| 5分钟 | 4小时 |
| 30分钟 | 24小时 |

例如从第1天07:00开始，正常运行5分钟后是11:00，30分钟后是第2天07:00。实现时以整数累计，跨午夜增加天数，不依赖手机、联网或校准现实日期。

## 2. 小猫的一天

以下作息为初版设计参数，区间均为左闭右开。例如08:00已进入上午，12:00进入午间。

| 游戏时间 | 日程氛围 | 主要活动 | 正常流速下的现实长度 |
| --- | --- | --- | --- |
| 06:00–08:00 | 早晨 | 起床、早餐、去教室 | 2分30秒 |
| 08:00–12:00 | 上午 | 上课、课堂记忆题 | 5分钟 |
| 12:00–14:00 | 午间 | 午饭、回宿舍休息 | 2分30秒 |
| 14:00–17:00 | 下午 | 上课、锻炼、校园活动 | 3分45秒 |
| 17:00–19:00 | 傍晚 | 晚饭、散步 | 2分30秒 |
| 19:00–23:00 | 晚间 | 自习、编程、小游戏 | 5分钟 |
| 23:00–次日06:00 | 夜间 | 回宿舍休息；仍可自主活动 | 8分45秒 |

时段提供生活安排，玩家继续自己点路、点门和选活动。到夜间不会强制传送回床、强制下线或锁住操作。

### 教室与食堂怎样变化

- 教室：08:00–12:00、14:00–17:00点原课桌为“上课”；其他时间为“自习”。记忆题仍可自愿参加。
- 食堂：06:00–09:00早餐、11:00–14:00午餐、17:00–20:00晚餐；其他时间为“简餐”。餐点窗口与日程氛围是两套相容的分类，允许08:30仍能早餐、11:30能午餐。
- 宿舍：编程、休息、外卖和取餐继续可用。健身房与校园道路继续开放，时段可改变推荐文案。
- 时间窗在小猫实际到达、开始活动时判定。走向课桌途中跨过12:00，到达后显示“自习”；已经开始的活动保留开始时的分类，不在中途换名字或重复结算。

首个时间增量沿用原主动活动收益与冷却。早餐/午餐/晚餐/简餐先改变名称和日程联系，不同时扩展食物商店和菜单。保留原有满值、低饱食、忙碌与冷却判据；非饭点的替代活动并不绕过这些规则。

## 3. 24小时加速与操作计时分开

当前世界的同一个经过时间参与走路、动作、衰减、外卖与存档。直接把现有全部计时乘48，会同时加速移动、灯光展示和Flash写入，因此新增独立日程钟。

| 时间用途 | 本次规则 |
| --- | --- |
| 游戏日期、时刻、时段与昼夜 | 正常运行时按48倍累计 |
| 走路、登床、进门、动作动画 | 保持现有实际播放节奏 |
| 记忆题的500ms亮起与250ms间隔 | 保持真实时长，输入阶段仍无倒计时 |
| 音乐和PCM送音 | 采样率与播放速度保持原样 |
| 外卖30秒、活动冷却 | 首个时间增量仍按原实际运行秒数，日程钟同步流逝 |
| 自动保存稳定期、写入节流与失败重试 | 保持原实际秒数，不能乘48 |
| 被动饱食消耗、被动心情与睡眠恢复 | 改为按游戏时间结算，采用下一节的新标定 |

首个增量先保留原“点床休息、再点床叫醒”。若以后加入“睡到早上”，需另行定义跳时对订单、冷却、数值和奖励的影响；本次不把未确认的跳时功能混入连续时钟。

## 4. 双数值如何配合新的一天

现版饱食每现实5分钟减1、清醒心情每现实10分钟减1，睡眠每现实分钟心情加3。引入日程后应重新标定被动变化，不能将旧衰减和新衰减同时运行，也不能把原变化直接放大48倍。

以下为AI初版参数，用于后续模型模拟和体验调优，尚无实测：

| 状态 | 饱食变化 | 心情变化 |
| --- | --- | --- |
| 清醒，每游戏小时 | −2 | −3 |
| 睡眠，每游戏小时 | −1 | +2 |

继续只有饱食和心情，两项均限制在0–100。主动吃饭、摸摸、上课、编程、锻炼、外卖和记忆题先保留当前收益；显示实际截断后的变化。时间不会自动执行上课、吃饭或替玩家领取贴纸。

用一份估算检查量级：清醒17小时、睡眠7小时，被动饱食消耗41；加上两次上课、一次锻炼、一次编程消耗24，合计65。三次食堂用餐恢复60，外卖仍可补充。这只是参数估算，不是已经通过的平衡测试；还需模拟不同路线、重复活动、少吃一餐和长时间休息。

实现要求：

- 分段推进与一次推进相同总时长，应得到相同日期、时间和数值。
- 清醒/睡眠切换时正确处理各自余量，不能通过反复睡醒刷恢复。
- 数值到上下限仍正常消耗计时余量，不积攒一大笔日后补发。
- 手账保持按页推进，跨午夜不清掉未完成愿望，不因换日自动发奖励。
- 没开机期间不消耗数值、不继续配送、不恢复冷却、不新增一天。

## 5. 显示、昼夜与声音

左上保留地点信息，并增加紧凑的“第1天 07:00 · 早晨”时间行；手账、状态和楼门仍易读易点，不恢复已取消的路标入口或路面路名。

晨、日、暮、夜优先用现有素材的色调变化试样，不生成四套整幅校园和四套室内底图。夜晚仍能辨认道路、小猫和房门；弹窗文字及操作控件保持可读，不随场景一起压暗。具体排版和遮罩需用生产LVGL帧检查后确定。

继续复用现有音乐与短音。声音模式独立保存，静音不影响日程，记忆题背景压低规则保留。先完成时间与昼夜，不另加一批音乐占用程序区。

## 6. 关机暂停与保存边界

保存的应是同一份快照里的游戏天数、日内时刻、计时余量、小猫数值、手账、声音模式与订单。开机恢复最后一次有效快照，不根据现实关机时长补算。复位不能重置到早晨、补发上课/贴纸奖励或重复完成订单。

旧格式1至5没有日程钟：升级时建议从第1天07:00初始化，原数值、场景、睡眠、订单、冷却、声音与已有手账按对应旧格式继续恢复。保持已有安全落脚点策略。

当前64字节格式5的载荷已排满。实现前需要比较“重新压缩布局继续64字节”和“扩展版本化记录”，评审容量、计时精度、旧记录扫描和中断恢复后再定；本方案尚未选择具体字节布局。继续使用现有专用双区和驱动，旧固件须对新版有效记录写保护。

走时本身会持续变化，不能让每次跳钟都重置“稳定3秒”的脏计时，导致永远无法保存；也不能每跳一分钟就写Flash。需设计受控的实际时间检查点，保留原节流，并明确以最近成功快照为恢复依据。持续走时、活动、失败重试与强制断电的恢复范围都要验证，不承诺断电零回退。

## 7. 实施顺序和验收

| 顺序 | 工作 | 验收重点 |
| --- | --- | --- |
| 1 | 纯C日程钟与保存方案评审 | 48倍整数推进、跨日、余量、关机暂停语义与旧档迁移方案 |
| 2 | 数值与活动分类 | 时段边界、到达时分类、分段结算、保留替代玩法、不重复奖励 |
| 3 | 时间显示和昼夜样板 | 四种氛围可辨、夜间可玩、控件清楚，原走路和音频速度正常 |
| 4 | 完整主机回归和构建 | 原生活路线、手账、记忆题、声音、存档与8MiB程序区 |
| 5 | 新固件实机 | 核对现实/游戏时间比、昼夜、活动节奏、模式保存和复位 |

重点固定输入包括：1.25秒＝1游戏分钟、75秒＝1游戏小时、30分钟＝1游戏天；23:59附近跨日；多日大步推进与小步累加；08:00/12:00/14:00/17:00课程边界；06:00/09:00/11:00/14:00/17:00/20:00用餐边界；活动跨时段；持续走时仍能保存；读旧档、未知新格式写保护与中断提交。
