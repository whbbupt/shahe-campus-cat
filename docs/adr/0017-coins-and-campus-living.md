# ADR-0017 小猫赚生活费与固定位置布置

状态：产品方向与固定位置布置由用户确认；价格/奖励为AI初稿。日期：2026-11-08。

背景：用户认为手账用途有限，希望小游戏赚金币，食物与家具需要购买，并授权替换；随后在两种家具方案中明确选择固定位置换款式。

备选A：固定位置购买永久拥有，可免费摆上/收起，不改变原房间路径与家具支撑，先建立完整经济循环。备选B：自由拖拽摆放，需要动态障碍/遮挡/编辑器和坐标存档，范围与验证成本更大。用户选择A。

决定：金币作为主要奖励；手账/贴纸生产入口改为生活商店，旧文档/固件与历史证据保留。四小游戏通关10金币，失败参与满5秒得2金币，主动退出0，所有有金币奖励的结算共用60秒冷却；初始30，余额上限9999。低饱食0仍可走路/玩小游戏。餐费6、点心3、外卖8，固定盆栽40/挂画60/桌面书架80；无付费充值、债务、随机开箱或签到惩罚。生活互动保留心情+2，不发金币。

食物现买现用，暂不引入背包。食堂开始吃才扣一次，外卖成功下单时扣一次、取餐不再扣；拒绝、取消、没钱、已满和忙碌无扣费。商品和奖励为AI参数，验收后可调整。

沿用64字节双区日志及原分区/驱动，格式8复用退役手账字段存金币和家具状态；这属于现有存档架构内的布局演进。读取1–7继承原生活/声音/RTC资格/冷却/已付订单，并一次初始化金币30；写8后旧7必须拒绝、零写擦。先保留旧产物，测试迁移、半写和重新加载后不重复发初始化金币。


### 每日签到补充
用户随后原话“每天可以有签到我觉得”。REQ-212按每日6金币饭钱、可信北京时间自然日、漏签无罚设计；数额/日期与存档策略由AI拟定。格式9利用原保留54–55字节保存领取日期，旧8拒新9，原架构/分区/驱动不变。
