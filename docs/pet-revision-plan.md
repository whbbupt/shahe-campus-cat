## 3. 时间与睡眠的具体落点

主世界采用**现实24小时**，首版按北京时间UTC+8显示；取消48倍作为当前默认方案。保留[ADR-0014](adr/0014-accelerated-campus-time.md)作为历史，新决定见[ADR-0015](adr/0015-real-time-campus.md)。

- 白天上课、夜间自习；饭点正餐，其余时间简餐。开始时锁定活动类型，途中跨时段不重复结算。
- 初稿：06:00起晨、08:00—12:00及14:00—17:00上课、17:00起傍晚、19:00起夜景。22:00提醒睡觉，22:00—23:00准备，23:00—次日06:00未休息显示困倦。
- 困倦先采用轻量反馈和温和收益调整，不叠加高频扣值；睡觉后解除，白天恢复正常。具体参数在实现前写入模型用例。
- 夜间仍可吃简餐、自习、轻小游戏和查看手账；休息可主动结束。睡眠不能把玩家困在几小时等待中。
- RTC与宠物运行计时分开。关机期间日历可继续走，小猫数值、外卖、冷却和奖励暂停，不补算离线饥饿或熬夜惩罚。
- 复位和完整断电分开测试。RTC是否能在所有供电状态下保时取决于实际硬件，未验证前不能承诺；失去有效时间时提示重新校准。

手机校时首阶段提供可验证的写入/回读通道和时间编码辅助。LightBlue用于测试；自动在每次连接时发送iPhone时间还需要对应手机端支持，不能把系统配对或连接成功描述成已经自动校时。

## 4. 容量不够时怎样处理

先区分程序区和运行内存。当前图片像素约占已用空间的八成，校园地面约3.64MB、四房背景约1.404MB，音乐PCM约0.609MB；不把源码文本大小当作固件占用。

1. 对现有分块图片试验SDK/LVGL支持的无损压缩，核对解压后的像素与原图一致，验证真实生产渲染和内存释放。
2. 检查未使用素材、重复图层及声音数据，按实际引用和链接结果精简；不先删除已承诺功能。
3. 解压可能节省Flash却增加RAM和处理时间，必须同时记录最大单图解码内存、缓存上限和实际帧率；不能只看压缩包变小。
4. 仍无法满足时，再做更轻的场景：有辨识度的限色像素校园、四间房和夜景样板。保留沙河路网、楼门关系、养成路线和小猫风格统一。
5. 换成像素不等于自动省空间。分辨率、色深、调色板、透明层和编码方式须一起控制，用实际构建比较。

每个增量要求链接程序区低于8,388,608字节；优先释放可供后续功能使用的余量。当前绘本原图和已实测固件先保留，素材替换前后可对照，不覆盖历史证据。

## 5. 视觉与交互方向

这轮使用frontend-design技能。主题仍是“生活在沙河校园的小猫”，画面服务于照料与走动。现有图先保留，特色放在会随作息变化的校园光线、室内生活细节和小猫反应。

- 配色沿用墨绿`#304C4A`、校园蓝`#456B77`、手账纸`#F8F3DF`、草木绿`#88AA92`、浅蓝`#DCEAF3`；异常用克制的暖红，夜景用深蓝色调。
- 字体继续用现有中文子集，正文16px、地点与时钟20px；优先复用字体，不为一行状态引入整套字体文件。
- 场景头部放地点和后续数字钟；蓝牙连接信息与声音设置收进状态页。蓝牙状态除颜色外有文字，免得只凭色点猜测。
- 以手账页签串起状态、声音和成长内容。新增内容应减少反复翻页找功能的成本；不恢复已取消的出行按钮、路标和路面路名。
- 如需像素版，先做宿舍与校门路口同尺寸样板，对比白天/夜晚和触摸可读性，再统一其余场景。
