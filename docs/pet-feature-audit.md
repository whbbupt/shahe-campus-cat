# 沙河校园小猫：功能盘点、缺口与市场调研

> 日期：2026-11-10　基线：`faf9e74`（v0.17.4）→ v0.18.0　用途：回答“现在有什么、哪些还没真正跑起来、市面上同类产品怎么做、下一步加什么”。本文是分析与决策材料，不替代 `01` 需求、`02` 设计、`04` 测试报告和 `manifest.yaml` 的证据索引。

## 1. 结论摘要

1. **产品主循环已经成立**：宿舍/教室/食堂/健身房/校园五场景、点地走动、饱食/心情、作息与宵禁、堂食与外卖 12 道菜、金币/签到/小游戏、家具布置、格式 10 存档、BLE 校时与手机状态、音频和安卓校时工具都有软件实现，历代主机与目标构建记录在 `04`。
2. **“还没跑起来”的主要不是主循环代码，而是四类边界**：① 交付目录原本没有 `.git`，历史不可追溯；② 本机最初没有 SiFli SDK/scons/ARM 编译器，目标固件无法复现构建（本轮已装 SDK 并构建成功，sftool 仍被应用策略拦截）；③ TC-260 整体实机、TC-268 安卓联调、真实 Flash 掉电/旧档升级、真实屏幕触摸与音质仍未执行；④ 内容虽多，玩家看不到“我收集了什么”，缺少长期目标。
3. 本轮恢复 Git 基线，按用户选择新增**校园图鉴**（REQ-221），并修复评审发现的 4 处真实交互缺陷（REQ-222）。主机 123 项 PASS（含实际 LVGL 9.4 渲染），**目标固件已构建（main.bin 4,537,196 字节），未烧录，真实屏幕待测**，这些边界已写入 `04`/`06`/manifest。
4. 市场调研的共性：Tamagotchi 靠“养育关系 + 收集/装扮 + 每日低摩擦”活 30 年；Neko Atsume 靠“低压力收集（Catbook/Album）”；Peridot 证明强联网宠物服务也会停服。对本项目的启示是**离线优先、收集可见、每日一件小事**，而不是堆传感器。

## 4. 市场调研：同类产品怎么做

### 4.1 Tamagotchi（万代，1996–）

- 官方 IR 资料：截至 2025-07-31 全球累计出货 **1 亿台**，海外占 **51%**，30 周年（2026-11）前把市场做到约 **1000 亿日元**；官方把吸引力归为“养育的乐趣”和“没有开关、不能把宠物丢在一边”。[Bandai Namco IR Newsletter No.82](https://www.bandainamco.co.jp/en/ir/library/newsletter82_special.html)
- Tamagotchi Uni 的玩法页：角色有**多种性格**，喜欢的食物/物品随养育变化；可做**时装与房间布置、手工饰品**；**Tama Walk 按真实步数**给材料；两台设备可一起玩、送礼、结婚得到稀有下一代；Wi-Fi 进入 Tamaverse 下载物品/参加活动。[How to play](https://tamagotchi-official.com/us/series/uni/howtoplay/)
- 可借鉴：收集与装扮是长期目标；每日低摩擦（走路/喂食）比复杂系统更有效；角色“个性”比参数表更能建立关系。
- 不适用：Wi-Fi 联机/全球活动需要服务和持续运营，本项目只有 BLE，且课程不要求云端。

### 4.2 Neko Atsume（Hit-Point，2014–）

- 官方玩法页把核心功能列为 **Catbook（猫图鉴）、Album（相册）、Shop（商店）、Remodel（改造）**；官方说明“基本只要看着屏幕就能玩”。[How to Play](https://www.nekoatsume.com/sp/en/about.html)
- 可借鉴：**低压力收集**——不惩罚离线、不强迫每日打卡，靠“下一次会来什么”的期待；图鉴/相册让已有内容被看见。本项目的 12 道菜图鉴正是这一机制的轻量版。
- 不适用：猫的来访与相册需要新美术与随机事件，当前 ROM/时间不适合一次做完。

### 4.3 Peridot（Niantic，2023–2025）

- 官方页：喂食、抚摸、小游戏（捡球/教动作）、装扮，带宠物**日常散步**并识别环境；通过和朋友协作**孵化基因独特的下一代**。[Peridot Mobile](https://playperidot.com/experiences/peridot-mobile)
- 同一页面已挂出 **“Saying Goodbye / What was Peridot?”**：强联网、依赖服务的宠物产品也会停服。
- 可借鉴：散步/探索能把“屏幕宠物”带进现实场景；但本项目不能把核心闭环押在联网服务上。**离线优先**是差异点，也是课程可交付性的保障。

### 4.4 对本项目的设计启示

| 市场做法 | 是否适合本项目 | 落地方式 |
|---|---|---|
| 图鉴/收集（Neko Atsume Catbook、Tamagotchi 角色/物品） | 适合 | 已做 12 道菜图鉴；后续可扩家具/访客，但受 12 位掩码与 ROM 限制 |
| 每日低摩擦小事（喂食/走路/签到） | 适合 | 已有签到、作息、外卖；可加“今日校园小事”，但不能变成惩罚 |
| 个性/亲密度/成长阶段 | 部分适合 | 需要新美术或至少新存档字段；当前只做“吃过什么”，不做进化 |
| 时装/房间装扮 | 适合 | 已有 3 件家具；扩展需美术与摆放规则 |
| 真实步数/体感（Tama Walk、Peridot 散步） | 高风险 | 板载 IMU 未接入，驱动/校准/功耗未知；周数紧张时不建议先做 |
| 联机/云活动（Tamaverse） | 不适合 | 板载无 Wi-Fi，BLE 只适合手机点对点；不做服务依赖 |

## 5. 候选功能与取舍

| 候选 | 用户价值 | 成本/风险 | 结论 |
|---|---|---|---|
| A. 校园图鉴/收藏 | 让 12 道菜、3 件家具、4 个游戏有“被看见”的长期目标 | 低：复用素材，只加 12 位存档与一页 UI | **本轮已做**（REQ-221） |
| B. 每日天气/校园小事 | 每天打开有变化，强化“校园生活” | 中：需要规则、文案、可能的色调/图标；容易变成噱头 | 未做，建议下一轮先做 3 天可验证的最小版 |
| C. IMU 体感散步/摇一摇 | 最贴硬件，差异化强 | 高：驱动、校准、功耗、误触发；本机无法验证 | 未做，需先做单轴采样预研 |
| D. 访客猫/相册 | 最像 Neko Atsume 的收集循环 | 中高：新美术、随机事件、存档位；ROM 与 8MiB 需核对 | 未做，等图鉴实机反馈 |
| E. 手机远程照料 | 延续 BLE 卖点 | 中高：协议、App、权限、断连；安卓实机未验收 | 未做，先把 TC-268 做完 |

## 6. 本轮落地与验证

- **REQ-221 图鉴**：`dishes` 12 位，堂食 bit0–5、外卖 bit6–11；`finish()` 动作完成才置位；格式 11 复用 `r[5]/r[7]`；`visible_key` 扩到 20 字节；首页入口 + 12 行只读滚动页；重生成 486 字中文字体子集。
- **REQ-222 修复**：布置弹窗只在宿舍空闲打开、离房清理；BLE 接受 `seated`；配送页专用文案；错房间走统一 `reject` 提示。
- **验证**：WSL Ubuntu + gcc 15.2.0，`tests/run_pet_tests.py` **123 PASS / 0 FAIL**（`evidence/pet/host_ui_lvgl_v0.18.0_20261110.txt`，含 LVGL 9.4 渲染与图鉴预览）；`check_trace.py` PASS。**目标构建已通过**（main.bin 4,537,196；ROM 4,610,718/8,388,608），但未烧录、未做真实屏幕/触摸、真实 Flash 掉电、真实手机 BLE；因此 TC-260/268 仍 pending；TC-270/271/273 只记主机软件通过，真实屏幕待补。

## 7. 给下一步的建议

1. 先让学生补 **SDK 构建 + TC-260/TC-270 屏幕证据**；图鉴若拥挤，按截图调行高/字号，不凭想象改版。
2. 图鉴实机通过后，再选 B（每日小事）做 3 天最小闭环；C（IMU）先写单轴采样预研，不直接接玩法。
3. 不新增联网依赖；若做手机远程照料，先把 TC-268 的安卓链路验完。
4. 保持“离线也能完整玩”的底线——这是 Peridot 停服给出的最直接教训，也是课程现场演示最稳的保障。
