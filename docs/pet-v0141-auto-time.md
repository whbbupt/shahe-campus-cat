# v0.14.1：连接iPhone后自动校时

本版新增读取iPhone系统时间服务（CTS）。校时在每次蓝牙连接时自动执行，建立连接仍通过LightBlue完成。首次需要时由手机确认配对，设备读取时间与时区、设置RTC并读回核验后，状态页显示“日期 · 自动校时”。原数字钟、昼夜、晚间休息和全部养成保留。

## 更新后这样试

1. 工程 `D:/project/sifli/course_starter/project` 已构建，沿用CodeKit Download；状态页确认 **v0.14.1**。原三个下载镜像/地址保持，不单独烧LCPU。
2. iPhone打开LightBlue，连接ShaheCat。若出现系统配对提示，确认配对；拒绝或超过等待窗口时，断开重连可再试。
3. 连接后等片刻，打开小猫“状态”。首次未校时会显示“等待手机自动校时”；设备设置并读回确认成功后显示 **“2026-… · 自动校时”**，主界面出现HH:mm。时间固定北京时间UTC+8，请与手机对应时刻核对。
4. 本轮测试直接连接即可，先不要写0004，便于确认时间来自自动读取。可以Read0004观察：成功读值包含实际时间、`state=synced;result=ok;source=cts`。
5. 等一分钟核对走时；断开手机后设备RTC继续走，再连接检查本次CTS/TIME日志。保存后复位与完整断电保时按原时间用例分别记录。

若已有有效RTC，连接前会显示已有时刻；请看状态页是否出现本次自动来源及新的TIME日志。状态文字记录最近成功的时间来源，重新连接阶段的日志用于判断该次操作是否完成。

## 没自动完成时

- 状态页显示“自动校时未完成，可重连”时，保留串口 `[pet:CTS]` 和 `[pet:TIME]` 日志；可以发送 `pet_ble_status` 查看目前阶段。回传版本、手机是否提示配对、画面与日志即可，不要反复重烧或重做旧外设测试。
- `discover`、`pairing`、`register`、`read-zone`、`read-time`依次是发现、配对和读取阶段；`sample-queued`只表示交给主线程。RTC核验成功会打印 `[pet:TIME] sync result=1 ... source=cts`，这里1是PT_OK。手机Read0004则用文字`result=ok`。
- 每步约8秒、配对等待30秒，一次连接至多请求一次配对，避免连续弹窗。手动备用0004仍保留，操作见[上一版说明](pet-v014-clock.md)，日程参数也沿用该说明。
- 发现/读取失败时，原有效时钟继续走；RTC设置异常会尝试确认旧值或回滚，无法确认有效时间时明确待校时。不会因断连重置饱食、心情、订单、手账或奖励。

请回传新版本的自动校时画面和日志。这一步依据工程AGENTS第C节：“涉及屏幕 UI 实际效果、蓝牙”必须取得真实证据后才能继续作出实机结论。当前TC-240尚未执行，主机截图不是本机iPhone实际配对成功证据。

## 软件验证与范围

SDK GATT客户端已启用，板子继续作为被手机连接的外设；未启用主动扫描手机。客户端复用既有BLE工作线程，回调拷贝有界值，不保存SDK临时指针，不在蓝牙线程设置RTC或更新UI。

严格处理CTS的10字节时间、2字节本地时区/DST和日期范围；先换算UTC，再按北京时间显示。未知时区、非法日期/长度不会写入RTC。读到的自动样本超过2秒即废弃，领取时补偿已过整秒；手动请求优先于尚未领取的自动数据。

真实适配假回调覆盖空/错服务、句柄0合法、资源失败、配对拒绝/重复事件/超时、错误与断连、同索引重连、满队列及有界复制。配对时其他系统服务的属性变化不会打断CTS；当前CTS句柄失效时停止并提示重连。原模型/世界/保存/音频/BLE四worker/SDK LVGL和生活路线全回归通过，状态页等待/失败/自动三态已查看原生主机预览；静态/移动50次刷新的大图解码仍0/0/3，不当作板端FPS。

存档实现与格式7保持，自动来源只在运行内存中，可信资格仍用原bit。旧1–6迁移与旧6对7写保护规则保留。SDK源码/构建骨架和宠物存档分区未改。后续短游戏与室内成长仍在[总清单](pet-revision-plan.md)。
