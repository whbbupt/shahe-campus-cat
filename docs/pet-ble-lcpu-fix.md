# v0.12.4 蓝牙核心镜像修复与验证

## 本版解决的遗漏

v0.12.3真实启动显示芯片Rev:3。SDK v2.5.1对这个版本需要加载LCPU程序，但此前小猫工程没有集成镜像，最终固件只保留了2字节的空加载函数。用户已明确授权修改构建文件，本版按同版官方BLE peripheral例程增加AddLCPU，由SDK构建并嵌入对应板型的蓝牙核心程序。

加载函数现已从空函数换成正式实现。最终ELF中的5,412字节镜像与本次生成的lcpu.bin逐字节一致，SHA-256为`59CAE739A19FE50EBB5D925B1E8B930F8EAE3AB1F44667CF023918425F8FC128`。这是构建遗漏的修复，是否已经恢复无线仍须板端测试。

## 构建与容量

程序区 **7,440,868 / 8,388,608字节（约88.7%）**，剩余 **947,740字节（约0.90MiB）**；比v0.12.3增加5,440字节。HCPU静态RAM仍为169,444字节。main.bin大小7,372,580字节，SHA-256为`17FFE226AA6C6DB4B7BF757CE048E04614E9BE8280027030278A35A804D5E412`。

LCPU是独立核心，其本次链接报告ROM6,723/12,288、静态RAM1,872/23,552字节；不能与HCPU静态RAM相加后当成同一块区域占用。LCPU镜像已包含于main.bin，下载仍为原三个镜像和地址，无需单独给lcpu.bin配置烧录地址。存档分区与原下载配置逐字节相同，旧v0.12.3完整15项产物已核验备份。

原BLE协议/回调/worker四场景及模型、世界、存档、应用驱动、音频、实际SDK LVGL回归通过。集成检查先在旧固件真实失败，再在本次最终ELF通过，并核对镜像来自LCPU子工程。增量构建保留原7条告警，新增LCPU ELF的RWX段提示1条；此前SDK潜在空指针相关文件本次未重编译，不能称告警已修复。
