# v0.14.2：修正iPhone配对请求角色

根据你提供的真实日志，上一版发出GAPC_BOND（op10）后返回66，随后校时超时。SDK中66是“当前配置不支持”；上一版错误调用了只可由中心设备使用的配对接口，小猫实际是由iPhone连接的外设。这是AI实现中的接口选择错误，旧主机mock未检查角色，原软件通过未覆盖到这个问题。

本版改为SDK的外设安全请求接口，由iPhone继续发起配对/加密。请求被拒绝时会直接记录原因，不再仅等待30秒；请求受理也不会误报校时成功。原RTC设置/读回、时区、数字钟、昼夜和养成继续保留。

## 更新后只需这样试

1. 工程 `D:/project/sifli/course_starter/project` 已构建，用CodeKit Download更新，确认状态页 **v0.14.2**。
2. 保持串口监视打开，在LightBlue连接ShaheCat。若iPhone提示配对，确认配对；本轮先不用写0004。
3. 观察状态页是否显示正确日期及“自动校时”，主界面时间是否正确。回传连接过程中的 `[pet:CTS]`、`[pet:TIME]` 日志及画面。
4. 若仍未完成，发送 **`pet_ble_status`**。本版即使先前日志没复制，查询也会保留具体 `reason`、`sdk` 状态、连接号、是否已请求/已加密，例如 `stage=unavailable reason=security-request-rejected sdk=66 ...`（这里只是格式示例，不是新实测）。

`[pet:CTS] security-request result=0`表示请求已提交；实际RTC核验成功还需 `[pet:TIME] sync result=1 ... source=cts` 及设备正确时间，或手机Read0004的 `state=synced;result=ok;source=cts`。没有弹窗本身不能判定成功/失败，请以日志和实际时钟为准。

这一步仍需按[工程AGENTS第C节](D:/project/sifli/course_starter/AGENTS.md)取得真实硬件日志/画面后确认。旧v0.14.1 TC-240失败保留，新TC-243尚待实测；角色错误修正不等于已经验证完iPhone CTS的全部兼容性。
